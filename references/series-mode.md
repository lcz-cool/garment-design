# 系列模式 Series

一次要出多个款（一季胶囊、一组 look、同色系三件套）时走这套。**系列不是整套**：整套是一个模特身上叠几件，系列是几个独立款共享一套色彩与面料逻辑。

判断很简单 —— **能不能分开穿着、分开生产**。能，就是系列；不能（打底 + 外套 + 裤 + 鞋），就是整套。

---

## 一、什么时候进系列模式

- 一次要 3 款以上**不同款式**（连衣裙 + 衬衫 + 长裤）
- 明确说「系列」「胶囊」「一组」「这一季三件」
- 款之间要横向对比（同廓形不同色 / 同色不同廓形）

**不适用**：3 件以上但都是一个人身上叠穿的 → 走整套；只有 2 款 → 逐款跑单件，别为两款开一套系列页。

---

## 二、交付结构

```
designs/<季节>-SERIES-<主题>/
├── series-spec.html            # 系列页，唯一入口
├── looks/<款号>.png            # 每款一张效果图，共用背景预设
├── flats/<款号>.png            # 每款一张平面图
└── specs/<款号>.html           # 每款一份单款设计稿（复用单件流程）
```

**系列页不放拼版大图。** 拼版图要么再花一张图去生成（成本翻倍且容易糊），要么在 HTML 里用 grid 排 —— 后者可点开放大、可加款号、可打印，没有任何理由选前者。

款号连号：`AW26-CT-001` / `AW26-CT-002` / `AW26-KN-003`，序号在系列内连续，不按品类各自从 001 起。

---

## 三、共享什么，独立什么

| 共享（先定死，全系列不改） | 独立（每款各自成立） |
|---|---|
| 风格锚点（一到两个） | 品类、廓形 |
| 色彩方案（3 色 + Pantone 近似 + HEX） | 主色在款式上的分配（主/辅/点） |
| 面料板（主料 / 里料 / 辅料 + 克重） | 每款用料比例与用量 |
| 季节档与克重区间 | 具体规格 |
| 号型基准 | 每款尺寸表 |
| 背景预设、光线、模特调性 | 姿态、镜头距离 |

**共享板必须先给用户确认再出图。** 6 款跑完才发现色板选错，是这类任务最大的浪费 —— 色板一错，六张效果图和六张平面图全部作废。

---

## 四、执行顺序

1. **解析**：逐款拆要素表，同时抽出各款共有的东西（同一个色？同一种面料？）
2. **定共享板**：色彩三个色 + Pantone 近似、面料板、风格锚点、季节档 → **停下来确认**
3. **出图**：逐款走单件流程（效果图 → 从效果图反推平面图），每款都用同一段背景与光线描述
4. **写系列页**：款表 + lookbook 网格 + 系列逻辑
5. **写单款页**：每款一份 `specs/<款号>.html`，共用系列页的色板与面料板，不重复论证
6. **自检**：`python scripts/check_spec.py <系列目录>`

**预算**：N 款 × 2 张（效果图 + 平面图）+ 返工上限 N 张。开跑前把总数报给用户；N > 6 建议分批，一批 3 款。

---

## 五、系列页怎么写

**目标读者是买手**：他要判断这几款能不能一起上货架，而不是逐款看细节。

### 必须有的四块

1. **款表**：款号 / 品类 / 廓形 / 主色 / 主料 / 一句话结构 / 链接到单款页。一张表看完整个系列。
2. **lookbook 网格**：每款一格，图 + 款号 + 一句话。背景必须一致，否则网格会散。
3. **系列逻辑**：为什么这几款是一组 —— 比例呼应（上短下宽 / 长大衣压短裙）、配色分工（谁做主色、谁做中性底、谁做点缀）、面料共用（同一块料出现两次以上）。
4. **共享板**：色彩与面料只写一次，标注「全系列共用」。

### 不要写什么

- 不要把每款的完整结构表塞进系列页 —— 那是单款页的事，塞进来买手会跳过
- 不要写「本系列灵感来源于自然与都市」这类空话，系列逻辑必须是可验证的比例关系
- 不要给每款都写「设计概念」，系列只有一个概念，款是它的不同解法

### 系列页的章节顺序

```
00 页眉（系列名 / 季节 / 款数 / 号型基准 / 版本）
01 系列概念（一段，三行以内）
02 共享色彩方案（色卡 + Pantone + 打色免责）
03 共享面料板（表格，含为什么选它）
04 款表（核心，买手先看这里）
05 系列 lookbook（网格，背景统一）
06 系列逻辑（比例 / 配色 / 面料三件事）
07 尺寸基准与放码（共享基准 + 逐款差异）
08 生产提示（共用面料的订量与分缸风险、先投产哪款）
09 设计假设（性别归属第一行，逐款默认值合并写）
```

## 六、常见翻车

| 现象 | 原因 | 对策 |
|---|---|---|
| 六款像六个品牌的衣服 | 共享板没定死就开始出图 | 先定色板与面料板并确认 |
| 网格里背景一块街景一块棚拍 | 每款各自写背景 | 系列内固定同一段背景描述，逐字复用 |
| 款与款之间没有关系 | 只做了「多款」，没做「系列」 | 06 节必须写出可验证的比例与配色关系 |
| 单款页与系列页色号不一致 | 两边各写一遍色卡 | 单款页引用系列页的色板，只写本款用到哪几个 |
| 每款都从零解释一遍面料 | 单款页重复论证 | 共享部分只在系列页写，单款页一句「沿用系列主料」 |
| 款数一多就统一糊掉 | 一次跑 8 款 | 分批，每批 ≤3 款，先出图后补文 |

## 七、系列变体

系列的「再来一版」不是重跑一遍 —— 换的通常只是**共享板**。换色板或换面料板，款与结构不动。

```
designs/AW26-SERIES-001-<主题>/
├── series-spec.html
├── looks/ flats/ specs/
└── variants/
    └── v2-换燕麦色/
        ├── series-spec.html      # 只改 02 色板 / 03 面料板 / 06 配色分工 / 版本号
        └── looks/<款号>.png      # 颜色变了，效果图必须重出
```

规则：

- **只改一个共享变量**：色板 或 面料板。两个都改，横向对比就不成立
- **款表不能动**。款、品类、结构一句话只要有一条变了，这已经不是同一个系列的变体 —— 新开一个系列
- **flat 可以不重出**：结构没变，直接复用主系列的 `flats/`。变体目录里不带 `flats/` 是正常的，不是漏文件
- **效果图必须重出**：颜色/面料变了，旧图不能拿来充数
- 版本号递增（v1.1 → v1.2），系列页 09 节写清「改了什么、哪些复用」
- 目录名带变量：`v2-换燕麦色`，不要 `v2`、`new`、`最终版`

**为什么不做「换廓形」的系列变体**：廓形一改，六款的 flat 全废、系列逻辑（比例呼应）也要重写 —— 那就是新系列，套变体的壳只会让两个系列互相污染。
